# Reality Design Lab website

## Local development and checks

The website uses Next.js, React, Tailwind CSS, and Contentlayer. Detailed project content comes from a separate Obsidian repository. Use Node.js 22 or newer and install dependencies with npm and `package-lock.json`.

```sh
ln -s ../Reality_Design_Lab vault
npm ci
npm run dev
```

Do not recreate the `vault` symlink if it already exists. `VAULT_ROOT` in `.env` identifies the content source, and `PUBLISH_ROOT` identifies the generated media directory. The tracked `.env` contains only public build settings; keep tokens and other secrets in the untracked `.env.local`.

```sh
npm run lint
npm run typecheck
npm test
npm run audit:content
npm run build
npm start
```

Run `npm run content` after editing the vault; the website does not watch it directly. `published: true` controls publication, while the legacy `draft` field does not. On the homepage, pointer hover starts a silent preview and clicking the cover opens the project. Touch-down starts a preview; releasing after a short hold lets it loop without navigation, while a short tap opens the project. Scrolling stops the preview only when its card leaves the viewport. Starting another preview stops the previous one.

The homepage warms at most two visible previews on fine pointers and one on touch devices. WebKit skips warming because its metadata request can download an entire H.264 file. Data Saver and reduced-motion preferences also disable warming. Browsers may download several seconds of video for `preload="metadata"`, so remeasure first-screen and full-scroll traffic before increasing these limits.

The published-asset audit rejects missing media, Git LFS pointers, and cover MP4s whose playback metadata follows the video data. Remux an affected MP4 with `ffmpeg -i input.mp4 -c copy -movflags +faststart output.mp4`; this preserves the encoded video while allowing playback to start without fetching the whole file.

## Deployment

Confirm the linked Vercel project, then run `sh deploy.sh` to create a preview. Verify its exact URL before running `sh promote.sh <verified-preview-url>`. Do not guess which deployment is the latest.

The vault repository's `.github/workflows/deploy.yml` is the automated production path. A push to the vault's `main` branch, or a manual workflow run, creates a staged production deployment. The workflow checks routes and media before promoting it to `reality.design`. GitHub Actions needs `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`, `VERCEL_TOKEN`, and `VERCEL_AUTOMATION_BYPASS_SECRET` repository secrets. Create the bypass secret under the Vercel project's Settings > Deployment Protection > Protection Bypass for Automation, then store it in the vault repository's Actions secrets. Missing credentials fail before the build. Never put a token in the repository or a chat message.

## Content and maintenance

- Obsidian stores full project records, publications, exhibitions, and original photographs. Notion also stores complete readable project records, images, exhibition options, publication details, and links back to the lab website.
- A project's `_archive` holds original images and provenance manifests. `_resources` holds images used on the website. Public Markdown references the optimized versions.
- `scripts/archive-media.mjs` downloads and verifies photographs listed in a manifest, records SHA-256 checksums, and creates WebP derivatives.
- `docs/maintenance/project-inventory.json` is generated by the content audit. A missing publications section is an editorial prompt, not necessarily an error.
- `skills/reality-design-lab-maintenance/SKILL.md` documents the maintenance workflow.
- `.cache`, `.contentlayer`, `.next`, `public/media`, and `output` are generated files or local verification artifacts, not authoring sources.

## Custom components

### Contacts & Contact

Contact information. Each `Contact` requires a `title` property.

```markdown
<Contacts>
   <Contact title="contact info">[dev@reality.design](mailto::test@website)</Contact>
   <Contact title="twitter/X">[realitydeslab](https://website)</Contact>
   <Contact title="linkedIn">[Reality Design Lab](https://website) </Contact>
</Contacts>
```

### Members

Member list. Separate members with blank lines, as required by Markdown.

```markdown
<Members>
Boxiong Zhao

Chu Zhang

..
</Members>
```

### Hide or hide

Wrap content that belongs in Obsidian but should not appear on the website in this tag.

```markdown
<hide>Hidden contents</hide>

<Hide>Hidden contents</Hide>
```

### ImageControl

Control the layout of an image embedded in Markdown.

```markdown
<ImageControl style={{height:"30rem"}} align="right">
![[image.png]]
</ImageControl>
```

## Configuration and generated files

In `.env`, `VAULT_ROOT` points to the Obsidian repository, `PUBLISH_ROOT` defaults to `media`, and `CACHE_ROOT` defaults to `.cache`. Do not copy the entire vault into `public`.

After `npm run content` compiles published content, it verifies referenced media and moves stale media, generated documents, and the legacy `public/static/vault` into `output/asset-quarantine/`. Original Obsidian files are untouched. Run `node scripts/prune-published-assets.mjs` for a read-only check. The report is written to `output/audit/published-assets.json`.

Missing media fails the build. Wiki links to unpublished or unresolved documents render as text. When documents share a name, use a qualified vault path such as `[[Projects/Composable Life/Composable Life|Composable Life]]`.

Do not let the development watcher and a release build write to `.contentlayer` at the same time. Stop the development server before a release build, then use `npm start` to inspect the production build.

## Frequently asked questions

### How do I configure a project in Obsidian?

```markdown
---
title: Title (required)
slug: Unique slug (required)
codename: Name shown in the sidebar (required)
type: Project (required, capitalized)
published: true
yearStart: 2018
yearEnd: 2019
cover: "[[image.png]]" (required default cover)
coverVideo: "[[video.mp4]]" (optional hover preview)
preview: (optional list of images shown at the end of the project page)
  - "[[image.png]]"
  - "[[image.png]]"
---

<!-- See defs/project.ts for the complete schema. -->
```

### How do I control publication?

Set `published: true`. The legacy `draft` field does not control publication.
